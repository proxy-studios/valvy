How Valvy Works

STEP 01

Zero-Config Launch

Call AutoConnect() on start. Valvy scans the network for existing hosts instantly.

STEP 02

Smart Fallback

No active host found? Valvy smoothly transitions into a host server and binds local client sockets.

STEP 03

Direct Socket Stream

Raw TCP/UDP streams transmit lightweight byte arrays without heavy serialized Netcode wrappers.

STEP 04

Automatic Cleanup

On disconnect or scene change, DontDestroyOnLoad components clear orphaned player objects automatically.

NetworkManager API

.Instance.AutoConnect()

Attempts to join target server IP. Automatically executes StartHost() if connection fails.

.Instance.StartHost()

Initializes the local ValvyServer and connects the local ValvyClient to localhost.

.Instance.Disconnect()

Stops server, disconnects client, clears synced entities, and resets status flags.

PlayerNetworkSync.cs

Modular component handling synchronized player transform dictionaries and lifecycle cleanup.

Frequently Asked Questions

Does Valvy require external server hosting?
No! Valvy supports host-client setups out of the box using raw C# sockets. You can host directly from a player instance or hook it into standard VPS servers.
Is Valvy compatible with Meta Quest / VR standalone?
Yes. Because Valvy relies strictly on standard C# System.Net.Sockets without platform-specific DLLs, it compiles cleanly for Android, Quest VR, and Windows builds.
How does Valvy handle player disconnects?
Valvy tracks client session IDs on the server loop. When a socket connection closes, a disconnect packet broadcasts to clear the associated player transforms cleanly.
